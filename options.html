How to spend less

Every request is billed for the text it carries in and for the text the model writes back, and a conversation is many requests. That leaves four things you can change.

  1. Carry lessFewer tokens of context in each request
  2. Pay a lower rateThe same tokens from the cache, or on a smaller model
  3. Send fewer requestsAbove all the ones an agent sends by itself
  4. Ask for less outputThe most expensive tokens on the bill

1 · Carry less into each request

Give the part, not the whole

If the answer is in chapter 3, send chapter 3. Every token you send is billed, whether or not the model needed it.

ConsiderYou have to know where to look. The model cannot notice what it was not given: a definition in the introduction, or a contradiction in another chapter.

Send text as text

Images are billed as tokens too, by their size in pixels and not by what they show. A page sent as a scan or a screenshot costs several times the tokens of the same page as text, and a PDF is usually read both ways at once.

ConsiderThe 2,500 tokens per scanned page are an example; the real number depends on the resolution and the model. Tables, formulas, figures and handwriting are often lost when a page is turned into text, and then the image is worth its price. Crop a screenshot to the part that matters.

Trim what is loaded every time

Before your first word, a tool sends its own instructions, the descriptions of every connected tool, and your project or memory files. All of that is carried in every request of the conversation.

ConsiderWith a warm cache this text is billed at the read rate, so it costs less than it looks, but an agent sends it dozens of times. Disconnect tools and servers you are not using and keep standing instructions short. What you remove the model no longer knows: cut what is unused, not what it needs.

Start a new conversation when the subject changes

Each message carries the whole conversation, including the parts that no longer matter. A second subject in the same thread pays for the first one in every message.

ConsiderWhile the cache is warm the old part is cheap, so the saving is small, as here. It becomes large when the thread holds a document or a long agent run, or when you come back after a break.

Compact a long conversation

Compacting replaces the earlier turns with a summary the model writes, and the conversation goes on from there. Coding agents have a command for it and do it by themselves when the context is nearly full; on the API it can be switched on.

ConsiderThe summary costs a request, and it replaces the cached conversation, so the first message after it is new input. Details are lost: an agent may open the same files again. Compact at a natural break, when one part of the work is finished, not in the middle of a step.

Hand over to a new session

Instead of letting the model summarise everything, have it write a handover note and start a new session from that note: the goal, what is done, what was tried and ruled out, which files matter, the next step. Use it to continue on another day, when the cache has expired anyway.

ConsiderThe new session knows only what the note says. Read the note before you close the old session, and keep it in a file so that a later session can start from it too. Within one sitting, continuing is cheaper than handing over.

Let a subagent do the searching

An agent can hand part of a task to a subagent. The subagent reads the files in a context of its own and returns only its conclusion, so the main conversation does not carry everything that was read. It can also run on a smaller model.

ConsiderA subagent starts cold: it loads its own instructions and knows nothing of the conversation except what it is told. On the same model the saving on one task is small; the gain is a main thread that stays short for the work that follows. For a small task it costs more than doing it directly, and several subagents at once multiply the bill.

2 · Pay a lower rate for the same tokens

Finish in one sitting

Text the model has just read stays in a cache for a few minutes: five at Anthropic, counted from the last use. Sent again within that time, it costs a few percent of the full rate. After a break it is billed in full.

ConsiderThe cache matches a conversation from its start up to the first difference. Editing an earlier message, switching the model or changing the attached tools discards everything after that point.

Choose the cache lifetime by the length of your pauses

On the API, and in some tools, the cache lifetime is a setting. Anthropic offers five minutes and one hour. Both are counted from the last use, and every use starts the time again at no charge. Filling the one-hour cache costs times as much as filling the five-minute one; reading costs the same.

ConsiderIf your messages are less than five minutes apart, the one-hour cache only adds cost. It pays for pauses of five minutes to an hour, and only if you do come back: text that is written to it and never read again was just more expensive. A chat app makes this choice for you.

Keep the cache warm with a ping

A request that reads the cached conversation and asks for no output starts the cache's time again and is billed only at the read rate. Sent shortly before the cache would expire, it keeps a five-minute cache alive through a longer pause.

ConsiderEvery ping pays for the whole context at the read rate, so pings add up while nothing happens. At these prices pings cost as much as reading the thread cold once: stop pinging when you will be away longer than that. A ping has to be sent by a script or by the tool you use; a chat app does not offer it.

Switch models between tasks, not in the middle of one

Each model has its own cache. After a switch, the new model has to read the whole conversation at its full rate, even if the old model had all of it cached. In a long thread that one message can cost more than the cheaper model saves.

ConsiderSwitching pays when much work is still ahead: the full-rate reading happens once, and every later message is at the new model's prices. For a new task, start a new conversation on the model that fits it; then there is nothing to read again.

3 · Send fewer requests

Tell an agent where to look

An agent's bill grows faster than its number of steps, because every step carries all the earlier ones. Naming the file, the error message and the way to reproduce it saves the steps spent searching.

ConsiderNarrowing the task takes your time, and sometimes you do not know where the problem is; then the search is what you are paying for. Look at what an agent loads by default: long instructions and many tools are carried in every request.

4 · Ask for less output

Ask for the answer, not the essay

An output token costs times as much as an input token, and in a chat the answers are most of the bill. Say how long the answer should be, and ask for the changed lines instead of the whole text rewritten.

ConsiderAn explanation you have to ask about twice costs more than one that was complete the first time.

Set the reasoning effort to fit the task

Current models reason before they answer. That reasoning is billed as output, at the output rate, even when you are shown only a summary of it or nothing. How much they reason is a setting: an effort level from low to max on Claude, or a thinking switch in a chat app. A higher level also makes an agent take more steps.

ConsiderThe amounts above are examples; how much a model reasons at each level depends on the model and on the question. The default differs between models, so check it instead of assuming. A wrong answer to a hard question costs more than the reasoning that would have prevented it: lower the effort for routine work, not for everything.

Before you optimise

  • Count the cost of a finished task, not of a message. Your own time is usually the largest part of it.
  • A subscription hides the bill but not the mechanics. Its usage limit counts the same work, so long threads, large attachments and larger models use it up faster.
  • Prices and cache rules change. The figures on this page are from 16 November 2026.
